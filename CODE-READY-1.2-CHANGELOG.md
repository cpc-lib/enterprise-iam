# CODE-READY SPEC 1.2 — Change Log

## Outcome

V1.2 extends the machine-readable implementation boundary from the first RBAC
loop to the remaining V1 authorization and file-security capabilities.

## Added

- SPEC 38 as the Core V1 authorization machine-contract authority.
- Phase 02 OpenAPI for organization, TeamRole, data scope and field policy.
- Phase 03 OpenAPI for sharing and file lifecycle APIs.
- Phase 02 AsyncAPI for organization, policy, share and file security facts.
- Physical DDL baselines for Organization, authorization policies, Sharing and
  File Service.
- Phase 02–05 security/integration/property acceptance catalog.
- Traceability rows for tree isolation, SQL compiler safety, mass assignment,
  share escalation/revoke fences and file isolation/scan/download.
- Multi-contract validation across every phase document and DDL owner set.
- Honest machine-contract coverage and quality-assessment matrices separating
  CODE-READY from Build/Production readiness.

## Preserved

- SPEC 37 and CODE PHASE 01 contracts remain the cross-cutting/RBAC baseline.
- No V1.1 endpoint or event was removed.
- Production-only choices remain explicit in the open-decision register.

## Not claimed

- This remains an implementation specification, not completed backend code.
- Full build readiness still requires compiling services, executable Flyway
  integration, container environments and implemented test evidence.
- Administration CRUD, operational APIs, file DR commands and deferred
  direct/temporary grants are not falsely labeled machine-complete.
